# src/ —— 宿主半身与模型层：记录读进来、读数算出来

> 本文件是路牌，上限 30 行：只写这一层有什么、什么时候看。

- 这一层有两半：**宿主半身**装在 DSH 宿主上把记录读进来；**模型层**把 mock 的读数逻辑搬成纯函数。改取数、改边界形状、改它对外那条接口时看这里
- `host/index.ts` —— 插件入口：装上 `ctx.pathfinderRecords`，对外只有一条 `read(sessionId, options)`。插件名 `pathfinder-records`；`workspaceFiles`／`sessions`／`sandboxPolicy` 三样到齐才 `apply`
- 工作区根按会话身份解析，次序固定：活着的会话头 → 落盘的会话头 → 沙箱策略记的那个根；有活着的会话头就不再问落盘那份。每次调用现算、不缓存，换个工作区或换条会话，读到的就是那一份
- `host/records.ts` —— 取数：只走工作区文件口子的 `list` 与 `read` 两个动作，对工作区只读，写回那一侧的口子没有进这一层；记录住在工作区里一层隐藏目录（`.pf`），四份来源是节点与线路、线路走过的步、指令、问题池，相对位置写在 `contract.ts` 的 `RECORD_SOURCES` 里
- 每份来源各报结局：`read`／`missing`（工作区里没有这一份）／`unusable`（读到了，但不是可读的 JSON，或形状对不上）。取不到就给空集合、读数照常返回——工作区里没有记录是一种正常读数
- 整份要分页读：口子对一页有字节上限，对请求的行数另有一档；这一页被拒就把页收小一半重取，只减不增。单行本身就超上限才算真读不动，那时只有那一份报 `unusable`
- `host/contract.ts` —— 边界形状：记录里原有字段的直通副本。字段一个都不改名、不换算、不折算时刻；记录里有的带过来，没有的不补默认值
- `model/` —— 模型层：把 mock 的读数逻辑搬成带类型的纯函数，四份记录原形＋一个时刻 → 那一刻的读数；不取数、不碰 DOM。改读数怎么算时看，类型检查 `npm run types:model`
- 单测在 `tests/`（宿主＋模型），`npm test` 一条命令跑全
