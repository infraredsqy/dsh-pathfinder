# pf-core · 动手之前必读

> 这份文件装的是这个仓的**法**：硬边界、记录落盘的口径、语料与测试的规矩。现状住在
> [api.md](api.md)（接口面）与 [merge.md](merge.md)（合并驱动）。
> 这里只放「不知道就会写错」的条文；读数、一次性的计划与报告不进来。

## 硬边界（`tests/guard.test.ts` 钉着，违反即红）

- 纯 TypeScript：源码树（`src/`、`tests/`）里没有 .py 文件；不出现 `@deepseek-ai/*`，不打开会话、不联网。
- 进程面只有一个入口——`pf-merge-ledger`（git 的合并驱动只能靠进程叫它）；没有 CLI、没有安装期脚本、仓库根没有 `bin/`。接口面里写了它的产物与出口。
- 引擎不管仓库：工作树、分支、提交、合并、工作树状态、git 那边的锁与目录布局都不是它的事，那些 git 命令由 agent 自己敲。注入的 git（`src/git.ts` 只有形状）只用来问 git 自己的事实——这个目录在不在 checkout 里、`info/exclude` 落在哪、项目根在仓库根下哪一段——以及经 git 自己的命令写、读配置里的两个合并驱动键。
- 「不起进程」这半是暂定的：管线宿主的半端会照常起进程。执行只能经 `PfOpenOptions.executor` 从外面注入。
- 私有包（`"private": true`），不发版；零运行时依赖，devDependencies 只许 typescript、tsdown、vitest。

## 记录

六种记录（节点、线、指令、问题、交接单、会话档）在磁盘上的格式逐字节定死：形状与词汇以 `src/types.ts` 为准，落点以 `src/paths.ts` 为准。记录与四份布局文件在任何平台都写 LF；给人读的文本产物（提示词、运行稿）随平台换行尾。

- 记录 IO 只有一处底座：JSON 读写只走 `src/jsonio.ts`（唯一读者与唯一写者，写是原子的），锁走 `src/ledgerlock.ts`（同进程与跨进程的写者互斥，持锁体内的再入放行），可判定的错误码在 `src/errors.ts`。别绕开底座手写记录 IO。
- 节点目录 `.pf/nodes/<id>/` 由 add 立起、remove 带走：add 只立目录、不立 spec.md（它的缺席就是「要求还没写」），run.md 由派发准备立起。
- 并行档（`worktree_mode` 为 `fork`）：工作树 `.pf/worktrees/<短 id>`、出口分支 `pf/<短 id>`；那几步 git 由 agent 自己敲，引擎不留那几步的记录、不做合回、也不替它写判决。

## 语料与测试

- 黄金语料一个用例一个目录（`tests/fixtures/<用例名>/`）：`input/` 是操作前的记录，`op.json` 是一次操作（参数按位展开、不经过 argv），`expected/` 是操作后的产物。`"expect": "return"` 的用例只比返回值，产物带当天日期的用例用 `"clock"` 钉死时钟。
- token 规则、比对尺子与生成侧入口都在 `tests/helpers/corpus.ts`：期望产物由它铺台生成，别手写。
- 新增逻辑补测试，且只锁不变量：锁冻结面、锁记录词汇、锁哈希不变，不锁易变的实现细节。测试都放 `tests/`；引擎操作（读写 `.pf` 记录）一律在临时目录做，完整套件前后仓库根 `.pf` 的哈希不变。
- 守卫扫版本库里的文本文件：来源词命中即红。白名单只有根路牌上那一句来源说明，按行放行，不是整份文件放行。

## 文档

- 路牌只放「这一层有什么、什么时候看」，一行一条、上限 15 行；目录的事归那个目录的路牌。
- 一个事实只住一处：能现算的（读命令、读代码）不写进散文；改一次要动两处，那就是冗余。
- 不写变更叙事（「原来……现在……」），不写被否的方案与原因；git 就是档案室。文档里不写行号、不写章节号，指针单向。
- 插件的声明（`plugin.json`）是唯一权威：旋钮、读数、度量、命令与文件都写在那里，文档只解释它们是什么意思，不抄第二份。

## 快档命令

- `pnpm typecheck`——tsc --noEmit
- `pnpm test`——vitest run
- `pnpm build`——tsdown；Node 22+，用 pnpm 装依赖
