# tests/ — The unit suite: what a test may pin, and what is walked by hand

> This file is a signpost, capped at 15 lines: one line per entry — only what this layer holds and when to read it.

**Pin the artifact, leave the wording alone.** What this suite keeps is behaviour and identity: the built browser half boots and draws without an error, registration and unmount land where they should, the model computes what it computes. The copy, the layout and the readings that need a real record move too often to pin — a test holding them costs an edit every time a word or a pixel moves. Those readings live on the hand pass in [../docs/publish.md](../docs/publish.md).

- `client-render.test.mjs` — The built `lib/client.js` over the in-memory port: the shell gets its spec, the panel mounts, every pane its tabs point at opens, the console stays clean. Skips itself with the reason when the bundle is not built; `npm test` builds it first
- `client-mount.test.mjs` — The two seats and the settings section: registration, the label function, unmount discipline, the language port
- `host-*.test.mjs` — The host half: the four sources, paging refusals, the writes' command lines, the session opener's flow, the dispatch relay — the claim a dispatch lands, the serial chain, the trigger behind the switch, and the button walking the same path (`host-relay`) — the package's plugin line, and the plugin skills placed into the DSH skill root, confirmed in a session's own catalog view, and taken back out (`host-skills`)
- `model-*.test.mjs` — The model layer: readings computed from the four records, one instant at a time, pure functions
- `helpers/` — The stand-ins the files share: the workspace-files port, the settings document, the locale service, the slot roster, the skill catalog's two views (root ranks and the layer merge, over real directories). One copy each; a file needing a narrower face builds it on top
- `package-surface.test.mjs` `runtime-outside-repo.test.mjs` — The package face (`files`, exports, the `bin` field, `engines`, the patch line, the `prepack` chain) that publishing depends on, and the shipped runtime assembled in a temp directory and run: `bin/` and the engine product it carries, with no checkout behind them
- `engine-inline.test.mjs` — The engine package's way in: it is a workspace package of this repo, no build external names it, and an entry importing it lands in the bundle as code rather than as a package reference. Skips the two legs that need `packages/pf-core/dist` with the reason when it is not built; `npm test` builds it first
- `fixtures/pf-cli/` — The drill's stage: one project's `.pf` records, plus the record files a real project keeps out of git (`overlay/`, pasted over each case's copy because a checkout only brings back tracked files), the stdout captured for each case (`expected/`), the two help listings (`help/`), and the case and id indexes beside them. These are captures, not output produced by a test run; the drill works on a temp copy, so a writing case leaves the stage as it was. A command line's printed bytes are its contract, so the drill pins those word for word — the panel's copy and layout stay unmeasured
- `pf-cli.test.mjs` `pf-cli-drill.test.mjs` — The `pf` command in front of the engine (`bin/`): the entry is one Node script with no platform branch, the help covers every word the router walks, and a drill over `fixtures/pf-cli/` runs the commands against a copy of a real project's records and compares the bytes with the ones captured beside them
