# tools/ —— 记录从哪来，测试床怎么起

> 本文件是路牌，上限 30 行：只写这一层有什么、什么时候看。

- `gen-ledger.mjs`、`gen-issues.mjs` —— 从一份真实 `.pf` 生成 `mock/ledger.js` 与 `mock/issues.js`（这两个文件不进库）。改数据来源时看
- `css-check.mjs` —— 样式层自查：`node tools/css-check.mjs`（`--root` 换根、`--quiet` 只印违例），对着 `mock/` 那十张表问 12
  组问题——颜色只走别名、圆角配 `corner-shape`、elevation 与中性描边、菜单材质、链接别名、两套主题都定义面板读到的别名
  （第 7 组另有一问：面板表的 `--pf-*` 有没有人声明）、记号对比度（明暗各一遍、24 行）、含义不同的同名类、模块挂接与
  href 断链、卡面悬停、令牌声明位置；全 0 违例 exit 0。设置那一节那张表内联在 `src/client/settings.tsx` 里，不在这个面里——那张表的颜色只走 DSH 令牌。改样式之后跑它
- `build-client.mjs` —— 浏览器半身的构建口：把面板要的那八张表从 `mock/` 取出来——`tokens.css` 与主面板那五张模块表收进 `.pf-page`，依赖与问题那两张（`field.css`／`register.css`）收进 `.pf-pane.is-embed`，另从设置表（`styles/settings.css`）里逐条明写取落点的那七条（舞台、框，加上设置那一列的版面：`.pf-configwrap` 与它里面那条滚动带、`.pf-config`、那一行、行尾那枚层签）——同一张表里还住着 `mock/h-settings.html` 那一页的规矩，所以不整张取；逐张收拢选择器：收拢前后各过一道尺子（页面根那批有没有落空、产物里有没有漏收的），再让 rolldown 把 `src/client/index.ts` 捆成一份 CJS，套进外壳要的 `window.__ModuleLoader__.load({ id, factory })`，落到 `lib/client.js`（`npm run bundle:client`）。改产物形状、改样式进包的方式时看
- `panel-check.mjs` —— 面板的自证夹具（`npm run check:panel`：先跑一遍构建口，再验产物）：把本仓 `.pf` 复制成四份**可写的**临时工作区（一份原样，一份经真工具造出「一个出局等人的格加第二条线路」，一份连 `.pf` 都不建的空工作区，一份 `.pf` 与四份文件都在、内容一份都不是可读 JSON 的坏工作区），用真宿主半身读它、把真产物挂进 jsdom，逐个看法点开（依赖那一格验记号与连线、三种读法、抠看，问题那一格验行与重量条、主从、状态分档）、在界面上点一次归档 / 复原 / 删除与三个策略数，每一项印读数；另有一节量「点一张卡切到那一格的会话」：真记录拷贝上那一层按节点分的小份笔记（`.pf/meta/sessions/`）与照真形状的会话清单、导航口子都接上，卡片三档实景各量一遍——那条会话在这台机器上、不在这台机器上、哪儿都没写会话，旧一版把会话写在记录本体上的那种写法也量一张；这一节自己往拷贝上经真工具加一格（还没人开过）、摘掉两份笔记、在记录本体上写一个 `dsh_session`；另把进包的每条规则与 `mock/` 那几张表逐条对一遍（只准重写选择器、声明一个字节不动）；调度中心那四处也各挂一遍、组件按真形状渲染（侧栏那一项、中央栏那一格、页脚徽标、浮层），空工作区与坏工作区各量一遍两处座席说什么；夹具还走一遍设置那两处——**设置那一节**（DSH 设置里那一页）这一层注册**五条**：设置里那一节加上那四处座席（按注册名册逐条断言槽位与 id / key，重复注册不落到槽位登记处）、在设置页里把四行都翻过（面板读数当场跟着变）、把同一份存储原样再挂一次（第二个实例的读数与设置页摆的值都对上）、最后扫一遍本地存储（先塞的四个旧键一个不剩、面板自己的键 0 个）；**设置那一格**（主面板第六格）另对着真工具走一趟：四行的值与行尾层签对着 `pf config list` 逐行比、四行各改一次（记录文件里真是那个值、层签翻到本项目）、两种非法值都不落笔（越界数字、候选表外的档位）、那一列的两枚把手（拖、方向键、双击回默认、上下限）、再挂一份新面板照同一条会话读一遍。控制台出现 error 就是失败；最后另走一趟装卸与热更新：「装 → 卸 → 再装」三步各量一遍四处清场点（侧栏项 / 页脚徽标 / 浮层 / 两张注入的样式标签）——三处座席既看名册在不在、也看屏上画没画出来。要亲手验一遍面板时看
- `testbed/` —— 与主环境完全隔离的 DSH 测试床：自己的 home、自己的 profile、自撰的合成工作区与合成会话。要亲手复现面板读到的东西、或验一条改动没碰主环境时看
- `testbed/testbed.ps1` —— 入口，一条命令三个动作：`up` 幂等重建测试床、把本仓这一条面板按本地路径装进 profile（走
  `dsh plugin --profile <名字> add <包目录>`，装的是产物）、起实例并留在那儿；`check` 跑完成判定、逐条印读数、失败非零退出；`down` 只收自己记下的那个实例（先核对命令行）
- `testbed/CHECKLIST.md` —— 那七行读数的单子：一行一条可重跑的命令 + 期望 + 实际读数。要交给 user 验收时看
- `testbed/testbed-lib.ps1` —— 上面那个入口的实现，不单独调用
- 运行实体一律落在项目树之外（默认 `%LOCALAPPDATA%\dsh-pathfinder-testbed`）；默认造一份工作区加一条会话，参数口子：`-Workspace` 换工作区名、`-SessionCount` 造第二条会话、`-EmptyWorkspace` 造一份空工作区、`-Plugin` 换要装进 profile 的那一份包（默认本仓，相对路径按调用时的当前目录归一）
- 两个脚本是 UTF-8 with BOM 的 PowerShell；写入只发生在测试床自己的根目录里，主 home 与本仓的 `.pf` 只读
