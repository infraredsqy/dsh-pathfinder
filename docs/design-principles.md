# dsh-pathfinder · 动手改界面之前必读

> 这份文件装的是**法**：词表与判据、共同地面、文案纪律、每一格的规矩。它不装现状、不装历史。
>
> **加任何内容需要 user explicit approval；上限 100 行，要加一条先腾出一条。**
> 「这一轮改了什么、为什么」写进 commit body；正在琢磨、还没定的写进 `.tmp/`（gitignored）。

面板是**记录的一张脸**：它印的字段都是工具里真有的，版面从记录里长出来。
一个没有单位的数字，读者读不出它是什么——宁可不印。

## 一、词表与判据

词表以工具仓的 `docs/vocabulary.md` 为准，本仓只引用、不另写一份，也不许各写一套读法。

- 节点的状态只有三个：`completed` / `shelved` / `todo`。
- `shelved` 是**出局等人**：没交付的判决落到图上就是它，谁都不许开工，要人 `pf dag revive`
  放回去。面板上读作**等待处理**。
- 「谁在做它」不在状态里，记在线路的 `holding` 里，读的时候算出来：`running`（在手）。
- `ready`（可开工）三条判据缺一不可：自己是 `todo`、每个依赖都 `completed`、**且没有任何线
  握着它**。少了第一条，出局等人的节点会装成可开工；少了第三条，别人手里正做的会装成可开工。
- 线路的 `path` 只记**走过的**步。「这条线还剩多少步」在工具里不存在——盘上没有这个数。

## 二、共同地面

五个值承担意义，其余都是结构；**面板不引入第六个色**。全部逐字取自 DSH 暗色主题。

| 记号 | 值 | 一个意思 |
|---|---|---|
| 已完成 | `rgba(255,255,255,.32)` | bulk，按质量读，不逐个读 |
| 在手 | `#7AAAFF` | 页面里唯一的亮色，只给正在动的东西 |
| 未开始 | 透明 + `rgba(255,255,255,.22)` 描边 | 空心，读成「还留着地方」 |
| 等待处理 / 失败 | `#F59E0B` | 出局等人与失败共用一色，不为它引第六个值 |

- 底是 `#151517`，`#1B1B1C` / `#232324` 分层，分界用白色透明发丝线。
- **字体三个角色都来自 DSH**：Montserrat 只给牌位，正文走系统无衬线，一切数字走等宽并带
  `tabular-nums`。字号只用 DSH 的档：24 / 20 / 16 / 14 / 13 / 12 / 11。
- **网格**：单屏 1440×900 里正文不许出滚动条，左右边距 24px，竖向节奏取 4px 的倍数。
- **任何 `vh` / `vw` 都不许用**：无头截图会在拍照前把视口撑大，凡是跟视口高度挂钩的尺寸都会
  在快门中间重排。
- **对比度下限**：结构色在底上只有 1.2–1.8:1，当不了承载数据的记号。判据落在读者身上——要
  逐个分辨的记号 ≥3:1；一整行按质量读的密排刻度可以到 `.14`。
- 共同构件住在 `mock/tokens.css`：两个面板说同一个词，就得说在同一个对象上。

## 三、文案纪律

- **不叙述界面。** 控件自己说状态，读数自己带单位；一句「这里显示…」都不写。控件需要一句
  解释时，把它做清楚——这比在它旁边添一行小字管用。
- **同一件事不说两遍。** 位置已经说过的不再抄一遍（所在的那一列不必在每张卡上各报一次）。
- **机器读数不进阅读流**（进度、内部评分、判定等级）。要留就降成 chip 或悬停。
- **时间一律静态。** 读的人是在别的活之间瞄一眼，一个读到一半就变的数字是读不完的数字。
- **不出现 session id。** 那串东西对读的人没有意义。
- **依赖只写两种词**：`可开工` / `前置 N`，且只写给还没开动的活——落定的不欠谁，在手的已经
  过了这个问题。
- **等待处理只在出问题的时候存在。** 一个都没有时不画它（不留灰 0、不留空框），那一列一个
  字都不占；有，它站在最左，读者先遇到它。

## 四、每一格

- **一根组织轴 + 一个签名件。** 一格只回答一个问句，签名件是它被记住的那件东西；共同的部分
  （牌位、工作区、读数行）在每一格里长得一样。
- **空的时候什么都不画**：不留空标题、不写「暂无」、不留带内边距的空盒子。退回「最近落定的
  几个」这类兜底时，判据要落在数据上，不落在状态旗标上——落在旗标上等于照一种读数设计、
  再给另一种打补丁。
- **折叠不动版面。** 它收掉的是内容，这一页的布局留在原地。
- 组合件（宽度把手、标签、行内动作、下拉）**照 DSH 自己那一份抄**，字号、字重、留白逐条对齐；
  只有 DSH 没有的东西才自己长。

## 五、平台事实（踩过的坑）

- Chrome **只在意两下 `click` 落在同一个元素上时才发 `dblclick`**。第一下若挪了 DOM 或滚了地界，
  这个事件永远不来——双击要靠 `click` 的 `detail`（连击数）自己认。
- `<button>` 造的卡片不写 `font-family`，拿的是系统的按钮字体（Windows 上是 Arial 13.33px）。
- `select` 的 `option` 墨色在 Chrome 里当继承值用，得单独给 `option` 上色。
- 行内文本比盒子宽时 `text-align: right` 分不出自由空间；这一路要用 `min-width: 0` 治，对齐治不了它。
- 只在悬停时显形的动作要用 `@media (hover: none)` 兜一层，否则触屏上够不着。

## 六、代码与注释

- 代码和注释**不写 md 路径、不写 §节号、不写行号**；判据的指针由 md 这一侧单向持有。
- 机制不显然的地方，把「为什么长成这样」写在它旁边——读完旁边那段代码就能看出这句话为真，
  才算写对了。
